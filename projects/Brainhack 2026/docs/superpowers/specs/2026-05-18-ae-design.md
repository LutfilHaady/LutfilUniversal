# AE Challenge Design — TIL-AI 2026

**Date:** 2026-05-18  
**Track:** Novice (fixed map)  
**Weight:** 40% of overall score  
**Scoring:** `sum(rewards) / num_rounds / 1000`

---

## 1. Overview

Two-phase approach: ship a working rule-based agent first (safe submission), then train a MaskablePPO policy overnight and swap it in if it outperforms the rule-based agent.

The only file written is `ae/src/ae_manager.py`. The server (`ae_server.py`), Dockerfile base structure, and routing stay untouched. Model weights are stored in `ae/models/` (git-ignored), baked into the Docker image at build time, and loaded at server startup. The container has no internet access during evaluation.

### Observation Format (per step, from evaluator)

```json
{
  "agent_viewcone":  "<7×5×25 float32>",
  "base_viewcone":   "<5×5×25 float32>",
  "direction":       0,
  "location":        [0, 0],
  "base_location":   [0, 0],
  "health":          [60.0],
  "frozen_ticks":    0,
  "base_health":     [100.0],
  "team_resources":  [0.0],
  "team_bombs":      3,
  "step":            0,
  "action_mask":     [1, 1, 1, 1, 1, 0]
```

The agent sits at **row 2, col 2** (0-indexed) of the 7×5 viewcone. Rows 3–6 are ahead; rows 0–1 are behind. The 25 viewcone channels are defined by `ViewChannel` in `til_environment/observation.py`.

## 3. Phase 1 — Rule-Based Agent

### Goal
A working, submittable agent that scores better than always-FORWARD. Target: reliable tile collection + basic bomb evasion.

### Cross-Step State
`AEManager` stores across steps (reset on `/reset`):
- `self.last_location: list[int]` — position from previous step
- `self.stuck_counter: int` — incremented when position unchanged, reset when it changes
- `self.last_direction: int` — to detect spinning

### Action Selection — Priority Order

Always filter every candidate action through `action_mask` before returning. If the chosen action is masked, fall through to the next priority.

| Priority | Condition | Action |
|---|---|---|
| 1 | `frozen_ticks > 0` | STAY |
| 2 | Any bomb (ally or enemy) with timer ≤ 2 within 2 cells in viewcone | Move in direction that maximises distance from bomb |
| 3 | `team_bombs > 0` and enemy agent visible in the cell directly ahead | PLACE_BOMB |
| 4 | Mission tile visible in viewcone | Navigate toward nearest (greedy turn + forward) |
| 5 | Resource tile visible (`team_resources < 1.5` or `team_bombs < 2`) | Navigate toward nearest |
| 6 | Recon tile visible | Navigate toward nearest |
| 7 | Enemy base visible in viewcone | Navigate toward it; PLACE_BOMB if adjacent |
| 8 | `stuck_counter >= 4` | Force turn RIGHT to break loop |
| 9 | Default | FORWARD; if masked (wall), turn RIGHT |

### Limited Lookahead (Rule-Based Only)
Before selecting FORWARD: check if the destination cell falls within blast range of any visible bomb with timer ≤ movement cost. If yes, treat the move as masked and fall through.

Before PLACE_BOMB: verify there is at least one unblocked escape path from the current cell after placing.

### Navigation Helper
To navigate toward a target viewcone cell `(target_row, target_col)` from agent position `(2, 2)`:
- If `target_row < 2` (behind): BACKWARD
- If `target_col < 2` (left of agent): LEFT turn, then forward next step
- If `target_col > 2` (right of agent): RIGHT turn, then forward next step
- Otherwise: FORWARD

## 4. Phase 2 — MaskablePPO Training

### Algorithm
`sb3_contrib.MaskablePPO` — PPO variant with native discrete action masking. Prevents the network wasting capacity learning that illegal actions are bad.

### Observation Preprocessing

Flatten everything into a **1514-dim float32 vector**:

| Field | Raw | Preprocessed | Dim |
|---|---|---|---|
| `agent_viewcone` | 7×5×25 | flatten | 875 |
| `base_viewcone` | 5×5×25 | flatten | 625 |
| `direction` | int 0–3 | one-hot | 4 |
| `location` | [x, y] | divide by 15 | 2 |
| `base_location` | [x, y] | divide by 15 | 2 |
| `health` | [float] | divide by 60 | 1 |
| `frozen_ticks` | int | divide by 3 | 1 |
| `base_health` | [float] | divide by 100 | 1 |
| `team_resources` | [float] | divide by 1.5 | 1 |
| `team_bombs` | int | divide by 50 | 1 |
| `step` | int | divide by 200 | 1 |
| **Total** | | | **1514** |

`action_mask` is extracted separately and passed to `model.predict(obs, action_masks=mask, deterministic=True)` at inference time — not included in the input vector.

### Environment Wrapper
Written as a custom `gymnasium.Env` wrapper around `til_environment.bomberman_env.Bomberman`:
1. Extract `action_mask` from obs dict, store for `action_masks()` method
2. Apply observation preprocessing above
3. Apply reward shaping (see below)
4. All rewards divided by 50 to keep values in ~[−1, 1]

Multi-agent handled via parameter sharing: convert AEC → Parallel API (`pettingzoo.utils.conversions.aec_to_parallel`), then SuperSuit `pettingzoo_env_to_vec_env_v1`. All 6 agents use the same policy weights.

### Reward Shaping

On top of default environment rewards:

| Addition | Value | Rationale |
|---|---|---|
| `step_penalty` | −0.01 per step | Discourages idle spinning |
| `stationary_penalty` | −0.02 on STAY | Extra penalty for camping |
| Exploration bonus | +0.05 per newly visible tile | Prevents base-camping |
| All rewards | ÷ 50 | Keeps value function stable |

Exploration bonus tracked per episode via a `set` of seen world coordinates, derived from visible viewcone cells each step. Reset on episode reset.

### Hyperparameters

```python
MaskablePPO(
    policy="MlpPolicy",
    learning_rate=3e-4,
    n_steps=2048,
    batch_size=256,
    n_epochs=10,
    gamma=0.99,
    gae_lambda=0.95,
    clip_range=0.2,
    ent_coef=0.01,
    policy_kwargs=dict(net_arch=[512, 512, 256]),
)
```

### Training Progression

| Phase | Opponents | Steps | Move on when |
|---|---|---|---|
| Random | 5 random agents | ~2M | Reward curve plateaus |
| Self-play | Current policy vs itself | ~3M more | Policy stops improving |
| Checkpoint pool | Mix of last 5–10 snapshots + current | Remaining time | Time runs out |

Save a checkpoint every 500k steps. Use the best checkpoint (by mean eval reward over 20 episodes vs random opponents) for submission, not necessarily the final one.

### Inference in Docker
```python
from sb3_contrib import MaskablePPO
import numpy as np

class AEManager:
    def __init__(self):
        self.model = MaskablePPO.load("../models/ae_policy")

    def ae(self, observation):
        obs_vec = preprocess(observation)           # → (1514,) float32
        mask = np.array(observation["action_mask"]) # → (6,) uint8
        action, _ = self.model.predict(obs_vec, action_masks=mask, deterministic=True)
        return int(action)
```

## 5. Deployment

### File Layout
```
ae/
├── Dockerfile          ← add: COPY models/ models/
├── requirements.txt    ← add: stable-baselines3, sb3-contrib, torch, supersuit
├── models/
│   └── ae_policy.zip   ← NOT committed (in .gitignore); download before til build
└── src/
    ├── ae_manager.py
    └── ae_server.py    ← unchanged
```

### Build & Submit Workflow
```bash
# On GCP Workbench after training:
til build ae
til test ae
til submit ae
```

No internet access inside the container — all weights must be local before `til build`.

### Swap Evaluation
Run both agents against 5 random opponents for 20 episodes using `til_environment`. Compare mean cumulative reward. Swap to PPO if it wins by >10% margin.

### Speed Score
PPO inference is a single MLP forward pass (~1ms). Speed score will not be a bottleneck.

## 6. Known Constraints & Risks

| Risk | Mitigation |
|---|---|
| PPO doesn't converge in time | Phase 1 rule-based agent is always the fallback submission |
| Self-play collapses to degenerate strategy | Checkpoint pool; revert to best past checkpoint |
| Docker image too large (torch + weights) | Use `--no-cache` build; check size limit (unknown — verify with organiser) |
| Reward shaping creates unintended behaviour | Monitor training curve; reduce exploration bonus if agent ignores combat |
| Fixed map in Novice → overfitting is fine | No mitigation needed; overfitting to the fixed map is the goal |
